# Agent 数据资产分析

此 Skill 用于把本机多个助理的历史工作转化为可解释的分析、评测和改进建议。优先通过 `agent_assets` MCP 查询数据，不要求用户提供内部编号。

## 工作流程

### 1. 判断是否已安装

先确认以下两项是否可用：

1. `agent-asset-expert status` 命令。
2. 名为 `agent_assets` 或 `agent_asset_expert` 的只读 MCP 服务及其查询工具。

若任一项不可用，不要臆测安装命令或手动改写配置。先读取本 Skill 所在目录上的 `./README.md`，使用其中“AI-Agent 一键安装”或“手动安装”的指引完成安装。

安装完成后：

1. 执行 `agent-asset-expert status`，确认已识别的平台。
2. 执行 `agent-asset-expert doctor`，确认 MCP 和本机数据目录状态。
3. 若检查结果提示尚无数据，向用户说明：需要先让已接入的助理完成一次真实任务，才能验证采集链路。
4. 安装或检查失败时，说明缺少的前置条件、失败位置和下一步，不要伪造查询结果。

## 2. 处理明确的用户意图

当用户的问题明确时，直接调用 MCP 提供的领域工具。先用助理名称和平台筛选，只有名称无法唯一定位时才向用户澄清，不要先索要内部编号。

| 用户意图 | 优先使用的 MCP 能力 | 输出重点 |
| --- | --- | --- |
| 查看某个助理最近一次工作 | `get_latest_execution` | 完成状态、结束原因、耗时、Token、是否具备完整过程。 |
| 查看最近工作或筛选失败任务 | `list_executions` | 按助理、平台、状态和时间范围列出工作档案。 |
| 复盘一次任务为什么失败或质量差 | `get_execution`、`get_execution_trace`、`read_content` | 用户诉求、最终回复、关键处理步骤、错误和可改进点。 |
| 比较多个助理的表现 | `summarize_execution_metrics`、`list_executions` | 完成率、Token、耗时、失败模式和样本量。 |
| 寻找可用于 Agent Evals 的真实案例 | `list_eval_candidates` | 失败、负反馈、人工修改或成功基线；说明筛选原因。 |
| 回答领域工具无法表达的统计问题 | `query_readonly_sql` | 仅使用一条带参数的可移植只读 `SELECT` 或 `CTE + SELECT`。 |

只在需要阅读具体内容时调用 `read_content`，避免一次读取无关的大内容。`query_readonly_sql` 是兜底能力，不能用于写入、修改结构或规避领域工具。

## 3. 用户意图不明确时

先用一句简短问题澄清用户希望得到什么结论，并把 MCP 能力翻译成用户可选择的场景。不要直接抛出工具名、字段名或内部编号。

可提供以下选项：

1. **评估某个助理的能力：**查看它最近的工作质量、常见失败原因和改进方向。
2. **统计任务完成情况：**查看一个或多个助理的完成率、平均耗时、Token 消耗和失败趋势。
3. **复盘具体问题：**查看某次失败、低质量或异常耗时任务的完整处理过程。
4. **比较多个助理：**比较它们在相同时间范围内的效率、成本和稳定性。
5. **准备 Agent Evals：**从真实历史中找出失败、人工修改、负反馈和优秀基线案例。
6. **查看数据覆盖范围：**确认本机接入了哪些助理、目前有哪些可分析的工作档案。

用户选择后，再按上一节调用相应 MCP 能力。

## 分析与表达要求

1. 先给结论，再列证据和建议；明确样本数量和筛选范围。
2. 将 `coverage=full` 且 `trace_integrity=complete` 的案例称为“可用于严格评测的完整案例”。其他记录可用于诊断，但要说明过程信息可能不完整。
3. 不将脱敏后的占位符当作可恢复的真实凭据，也不展示不必要的敏感内容。
4. 数据不足、名称不唯一或 MCP 不可用时，明确说明限制，并提出一个最小的下一步问题或操作。
